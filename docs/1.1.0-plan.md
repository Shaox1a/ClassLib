# ClassLib 1.1.0 优化需求与验收方案

状态：用户已批准，已实现并完成本地自动测试与真实浏览器验证；云端验证结果见文末。

本方案对应本轮四项优化，版本为 1.1.0。下列条目作为实现规范及验收清单。

## 1. 取消上传文件类型和大小限制

- 教师和管理员可以上传任意扩展名、无扩展名和任意二进制内容的文件，包括脚本、可执行文件和原白名单以外的格式。
- 文件选择器不使用类型白名单；本地上传、云端签发上传凭据、上传完成确认均取消扩展名白名单和内容签名匹配限制。文件内容与扩展名不一致也不作为拒绝理由。
- 不设置应用层单文件大小或整批总大小上限，移除现有 50 MiB 限制；前端、上传处理器、表单、签发凭据、完成确认和存储读取路径须同步调整。空文件也允许上传；声明大小须为非负整数，完成后按实际存储字节数核对并登记。文件名仍须有效且不超过 255 个字符；同文件夹内不覆盖同名文件。
- 文件类型用于列表显示和元数据记录，不再决定上传资格。无法推断 MIME 类型时使用 `application/octet-stream`。
- 上传对象继续私有保存，使用服务端生成的存储 key；下载经鉴权后以附件交付，HTML、SVG、脚本等文件也按下载处理。
- Supabase bucket 配置须取消额外的 MIME 类型与文件大小限制，项目全局上传配置也须核对，避免只修改应用代码后仍被旧的 50 MiB 配置拦截。
- 平台边界：应用不主动限制大小，但磁盘容量、存储服务的全局/套餐/协议上限和网络条件仍可能阻止上传。生产上线前须实查平台配置并记录实际能力；遇到平台限制时明确显示原因。若要满足实际文件需求必须升级套餐或更换存储，先说明具体方案和费用，不能静默改回应用限额，也不将本方案表述为物理上无限容量。参考 [Supabase 上传限制](https://supabase.com/docs/guides/storage/uploads/file-limits)。

## 2. 一次选择并上传多个文件

- 上传页面允许一次多选，将所有选中文件上传到当前文件夹，仍支持只选一个文件。
- 页面展示上传队列，每个文件显示名称、大小及状态：等待上传、上传中、确认中、成功、失败；失败项显示具体原因。
- 默认逐个上传。选择文件后点击一次“上传”即可开始整批处理，无需用户为每个文件重复操作；过程中限制重复提交。
- 本地和生产环境提供相同的多选体验。本地逐文件流式写入，云端使用临时授权直传；大文件采用分块/可续传上传，文件本体不经过 Vercel。参考 [Supabase 可续传上传](https://supabase.com/docs/guides/storage/uploads/resumable-uploads)。
- 每个文件独立校验和保存。一项失败时继续处理其余项，已经成功的文件保留；完成后展示成功/失败数量，并提供返回当前文件夹的入口。
- 同批同名文件按选择顺序处理：第一个符合要求的文件成功后，后续同名项提示冲突；已存在于目标文件夹的文件不覆盖、不自动改名。
- 允许对失败项单独重试；成功项不重新上传。网络中断导致“确认结果未知”时优先重试确认，服务端不得重复登记同一个上传对象。
- 登录过期或上传权限失效时暂停队列，提示重新登录，避免剩余文件反复失败。
- 本地与云端均避免将完整大文件或整批文件读入内存。云端完成确认以存储元数据核验字节数，最终对象整理采用存储端操作，不下载完整文件到 Django 再上传。保持临时对象隔离、不可覆盖已确认对象和确认重试幂等；上传凭据有效期与大文件耗时匹配，过期可恢复或重新申请凭据。状态提示适用于桌面和手机浏览器。

## 3. 增加列表（详细信息）视图

- 资料库首页、文件夹内容页和搜索结果页增加“大图标 / 列表”切换，默认维持大图标模式。
- 大图标模式保留现有浏览入口；列表模式使用表格呈现相同的文件夹与文件，不改变访问权限、搜索条件和分页结果。
- 列表的四列固定为：**名称、修改日期、类型、大小**。文件夹排在文件之前，各组默认按名称排列；搜索结果保留现有文件排序和分页。
- 点击名称进入对应文件夹或文件详情页；文件夹当前管理操作和文件详情中的下载、重命名、移动、删除继续可用。
- 视图选择记在当前浏览器中，切换页面或刷新后仍生效；存储不可用时仍可切换，本次选择不因存储错误而阻塞页面。
- 窄屏列表可横向滚动，长名称支持换行；切换按钮有当前选中状态，名称链接和视图切换可通过键盘操作。

| 列 | 文件 | 文件夹 |
| --- | --- | --- |
| 名称 | 完整显示文件名，包含扩展名 | 显示文件夹名 |
| 修改日期 | `File.updated_at`，显示为 `YYYY-MM-DD HH:mm`，时区为 Asia/Shanghai | 新增 `Folder.updated_at`，采用同样格式 |
| 类型 | 按最后一个扩展名显示，如 `PDF 文件`、`DOCX 文件`；无扩展名显示“文件” | 显示“文件夹” |
| 大小 | 按实际字节数格式化显示 B、KiB、MiB、GiB、TiB 等；悬浮说明或辅助文本提供精确字节数 | 显示 `—`，不递归计算目录大小 |

修改日期的定义：文件创建时等于上传时间，重命名或移动时更新；文件夹创建、重命名、移动时更新自身时间。本轮不将子项变化递归传播到所有父目录。已有文件夹以 `created_at` 回填修改日期，避免全部显示为升级时间。搜索中继续提供所在路径信息，便于区分不同目录下的同名结果。

## 4. 登录失败时保留已输入密码

- 用户提交错误的用户名或密码后，当前页面显示现有的通用登录错误提示，用户名与密码输入均保留，可直接编辑后再次提交。
- 密码框继续使用遮罩，默认不以明文显示。
- 优先采用页面内提交并在认证失败时保留原输入框的方式；密码仅保留在当前页面输入状态，不写入 URL、日志、cookie、session、localStorage、sessionStorage 或分析事件，也不由服务端回填进响应 HTML。
- 网络错误时保留输入并显示可重试提示；认证失败不刷新整个页面。保留 CSRF 校验、停用账号限制和安全的 `next` 跳转处理。
- 登录成功正常跳转；刷新、关闭页面或离开登录页后不提供应用层密码恢复。浏览器密码管理器自身行为由浏览器控制。
- JavaScript 不可用时仍允许普通表单登录；失败后保留密码的交互以 JavaScript 启用为条件，普通提交不由服务端回显密码。

## 6. 验收标准

| 编号 | 场景 | 预期结果 |

| A1 | 上传 `.exe`、`.py`、HTML、无扩展名、任意二进制及扩展名不匹配文件 | 本地、云端均不因类型或签名拒绝，下载内容与原文件一致 |
| A2 | 上传 0 字节、1 字节、50 MiB、超过 50 MiB 和 GiB 级文件 | 均不因应用大小限额拒绝；在存储可用范围内成功并核对实际字节数和下载内容，覆盖声明大小不符的拒绝场景 |
| A3 | 无效文件名、重复文件名、学生或未登录用户请求上传 | 仍按文件名、冲突和权限规则拒绝；前后端一致 |
| B1 | 一次选择三个不同类型文件并提交 | 一次操作完成队列，逐项状态和汇总准确，三个文件出现在当前文件夹 |
| B2 | 队列含存储空间不足、同批同名、已有同名及网络失败项 | 失败显示原因，其余文件成功；重试仅针对失败项，确认重试不重复登记 |
| B3 | 本地和生产多文件中含超过 50 MiB、GiB 级文件，模拟中断及凭据过期 | 本地流式写入，生产分块/可续传直传；可重试或恢复，最终字节数与元数据一致，确认阶段不将完整对象读回 Django，内存使用不随完整文件大小增长 |
| B5 | 核对云端项目全局和 bucket 大小配置，触发实际平台上限 | 旧 50 MiB 附加限额已移除；平台能力和限制有记录，错误能区分平台容量/上限与应用校验，不静默吞掉失败 |
| B4 | 上传期间会话或权限失效 | 队列暂停并提示重新登录，不错误标记为成功 |
| C1 | 首页、文件夹页和搜索页切换两种视图、刷新、跳转 | 同一批内容可浏览，选择持续生效，筛选和分页保留 |
| C2 | 查看文件夹、无扩展名文件、常见及未知扩展名文件 | 四列完整，类型和大小规则正确，搜索结果路径可辨识 |
| C3 | 升级旧目录，创建、重命名、移动文件和文件夹 | 历史目录日期正确回填，后续修改日期按定义更新，账号和原有文件内容不变 |
| C4 | 手机窄屏、键盘操作、浏览器存储被禁用 | 列表仍可操作，无字段丢失，视图切换不报错 |
| D1 | 输入错误密码并提交，随后编辑为正确密码 | 同一页提示错误且原密码仍遮罩保留，修正后成功登录 |
| D2 | 错误用户名、停用账号、网络失败、无效 CSRF、外部 `next` | 保留既有认证约束，不泄露密码，不允许外部跳转 |
| D3 | 检查错误响应、URL、日志及浏览器存储 | 密码未被应用写入上述位置，服务端返回的 HTML 不包含输入密码 |
| D4 | 禁用 JavaScript 后登录 | 普通表单可登录，失败响应不回填密码 |
| R1 | 管理员、教师、学生核心流程回归 | 登录、权限、搜索、上传下载、重命名、移动和删除正常，标签功能仍不存在 |

验证应包括相关自动测试以及真实浏览器的多选、列表切换与登录失败交互。生产 Supabase 路径在获准部署时单独验证，不能仅凭本地测试宣称完成。

## 7. 实施与验证记录（2026-11-22）

- 已实现四项优化，移除应用 50 MiB 限额及类型白名单；本地临时文件流式写入，云端签名 TUS 分块上传并按元数据确认。
- 46 项 Django 测试通过；真实 Edge 验证密码保留、多选空文件/二进制/51 MiB 文件、列表与浏览器偏好、搜索和窄屏布局；模拟网络中断验证从已完成的分块偏移恢复。
- 本地及生产已应用 `0004_folder_modified_date`，生产账号和文件数量保持不变。bucket 的 MIME 类型和额外文件大小限制均已设为 `null`。
- 平台实测：Supabase 对 1 GiB 长度申报返回 `413 Maximum size exceeded`。应用不设上限不代表当前平台可上传无限大小；本轮未升级付费套餐。更大云端文件需要单独调整平台能力。
- 追加真实传输验证：本地 Edge 完成 1 GiB 文件上传；连接实际 Supabase 的浏览器完成空文件、二进制文件及 13 MiB 签名 TUS 分块上传。相关测试目录与文件已在测试结束时清理。
