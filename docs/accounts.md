# 账户与权限组（1.2.0）

每个账户的业务信息为固定 ID、唯一昵称、密码哈希和一个权限组。数据库保留内部主键来关联上传文件、文件夹；原 `username` 列作为不可修改的登录 ID，原账户升级时不改变 ID、主键、密码或资料归属。昵称初始取原 ID，再按私有清单更新。旧的固定 `role` 字段迁移为权限组外键。Django 内部的会话和管理标记继续保留，网站权限只以当前权限组为准。

## 登录和个人信息

- 登录支持 ID 或昵称加密码。昵称唯一，且不能与其他账户的 ID 重复，避免同一输入指向多个账户；使用精确匹配。
- 导航“账户信息”顶部只显示 ID、权限组；昵称直接在下方表单查看、编辑，密码只提供修改输入。密码只保存哈希，不显示原密码或哈希。
- 本人可修改昵称和密码；修改密码时校验当前密码、确认新密码并保留当前会话。仅修改昵称无需填写密码。
- 手动设置的新密码沿用 Django 密码校验。创建时留空、管理员批量重置时，密码按私有清单规则取各自的 ID。
- 上传者显示当前昵称，资料仍通过不可变的内部主键关联账户。

## 管理账户

`/accounts/` 提供创建、编辑、多选、全选。管理员可以修改任意账户的昵称、密码、权限组和启用状态，ID 只读；原密码不可查看。可以创建管理员账户。

批量操作包括重置为各自 ID、移至指定权限组。只处理选择的账户；空选择、无效账户、无效目标组均不会部分执行。密码重置使旧密码和其他旧登录会话失效。更改本人密码时更新当前会话。

网站账户管理使用带 CSRF 的表单、服务端权限检查及事务。Django `/admin/` 中的账户记录仅允许查看，避免从另一入口绕过账户编辑规则。

## 管理权限组

`/groups/` 可添加、编辑、删除权限组。名称唯一；权限分别为：

| 权限 | 功能 |
| --- | --- |
| 浏览资料 | 首页、文件夹、文件详情、搜索 |
| 下载文件 | 下载私有文件 |
| 上传文件 | 上传页面、本地上传、云端上传凭据与确认 |
| 管理资料 | 新建文件夹、重命名、移动、删除文件和文件夹 |
| 管理账户 | 创建、编辑、启用/停用、批量重置与分组 |
| 管理权限组 | 添加、编辑、删除权限组 |

默认学生组可浏览、下载；教师组再加上传和管理资料；管理员组拥有全部权限。每个请求读取当前组权限，改组或改权限不需要重新登录。保留 `is_superuser` 标记也不能绕过网站组权限。无浏览权限的账户默认登录后进入账户信息页。

有成员的组删除前必须选择接收组，删除和转移成员一起执行。所有管理变更须保留至少一个已启用、同时具有账户管理和权限组管理权限的账户；不满足时全部回滚。

## 私有账户清单

私有清单由维护者保管，请使用清单中对应环境的账户。

先备份本地数据库，确认当前终端未配置远程数据库，再执行：

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py sync_accounts 账户.md --environment local --dry-run
.\.venv\Scripts\python.exe manage.py sync_accounts 账户.md --environment local --replace
```

替换清单保留同 ID 账户的内部主键，重设清单中账户的信息、密码、权限组并启用；移除清单之外的账户，清空旧会话。清单外账户仍拥有受保护的文件时会拒绝并回滚，不能静默改写上传者。启动脚本只迁移数据库，不会每次启动重置密码。已改动过的权限组权限不会因重导清单而被恢复为默认值。

部署端替换命令为 `--environment production`，仅允许明确配置的 PostgreSQL。先备份生产数据库并确认清单的管理员及历史资料归属。首次切换旧的姓名登录账户时，在账户结构迁移前一次性匹配清单中的昵称、分配新的固定登录 ID；旧管理员对应清单中的 管理员账户。保留内部主键及文件上传者关联，然后执行结构迁移和清单替换。此后 ID 不再修改。完整清单和迁移备份保持私有。

## 验证

```powershell
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py test accounts library
```

覆盖 ID/昵称登录、ID 不可变、唯一性、个人密码校验、哈希不泄露、管理越权、批量事务、权限即时变更、最后一个管理员保护，以及账户清单验证与替换。
